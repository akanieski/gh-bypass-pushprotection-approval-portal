A minimal update to the original bypass-and-dismissal proposal: preserve the native request, add an external quorum, and execute through a GitHub App.

Customer-hosted custom solution. This proposes a custom integration to be built, hosted, operated, and maintained by the customer, not a new GitHub product feature or a product-roadmap commitment.
Recommendation. GitHub does not provide a configurable two-approval quorum for these requests. Require two distinct eligible non-requesters to approve in an existing authenticated approval system; only then may the bridge approve the native bypass.

Execute through the App.

The existing approval system notifies reviewers with a request-specific portal link. For visibility inside GitHub, optionally create a restricted issue with reviewer mentions and that link. The issue is notification only, not approval evidence.

The minimum pilot

App + scheduled worker

Use installation tokens. Poll requests and votes, validate current native state, submit the decision, and reconcile uncertain results. No webhook endpoint required.

Existing approval system

Reuse authentication, two eligible reviewers, notifications, and portal. Do not grant native bypass rights just to send the approvers GitHub emails.

Protected ledger + alerts

Retain request identity, actor IDs, votes, timestamps, and confirmed outcome. Reuse approval storage if adequate; otherwise add one managed table. Protect the App key.

Controls that stay in scope

  • Trust verified votes. Exclude requester and duplicate votes; recheck eligibility. Link the final GitHub review to protected evidence. Names in a comment are not two native approvals.
  • Fail closed. Serialize finalization; handle expiry, changed requests, pagination, time windows, and retries. Outages never become approvals. Never put secret values in issues, notifications, URLs, or logs.
  • Keep discovery separate. The resource link helps developers; approvers receive deep links. No documented API injects a custom button or standalone pre-decision comment into the native request page.
Boundary: owners and security managers retain native bypass rights; govern and monitor these exceptions. Native approval can also permit future commits containing the same secret, so this is not per-commit enforcement.

Scope: one organization, one repository, fixed two-person push-bypass policy. Defer alert dismissal, arbitrary quorum counts, bots, dashboards, and multiple channels. Validate App permissions and the chosen approval product in the target deployment before rollout.
